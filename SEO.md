# SEO Documentation — B. Van Sanders Website

Production-ready technical SEO for the B. Van Sanders artist storefront (Next.js 16 App Router).

## 1. SEO Architecture

All SEO configuration is centralized in **`src/config/seo.js`**:

- Site identity, default title/description, keywords, Open Graph defaults
- `siteUrl` — read from `NEXT_PUBLIC_APP_URL` (fallback `http://localhost:3000`)
- `absoluteUrl(path)` — resolves relative paths to absolute URLs (used by canonicals, sitemap, robots, and JSON-LD)
- `kindLabel(kind)` / `kindAltPhrase(kind)` — consistent wording for originals / prints / gallery

Flow:

```
src/config/seo.js  →  root metadata (layout.jsx) + per-page metadata (pages)
                   →  sitemap.js, robots.js, manifest.js
                   →  JSON-LD (src/components/seo/JsonLd.jsx)
```

## 2. Sitemap Behavior

- Route: `/sitemap.xml` — generated by `src/app/sitemap.js`.
- Includes: `/`, `/about`, `/originals`, `/prints`, `/gallery`, `/contact` + every public product page (`/product/[id]`).
- Product list = seeded catalog (`src/data/products.js`) **merged with live Firestore products** fetched via the REST helper `fetchAllProducts()` (`src/services/firebase/rest.js`). Firestore failures fall back to the seeded catalog so generation never breaks.
- `lastModified` uses each product's `updatedAt` when present; `revalidate = 3600` refreshes it hourly.
- Private routes are **never** included: `/login`, `/forgot-password`, `/checkout`, `/checkout/success`, `/orders`, `/admin`.

## 3. Robots Behavior

- Route: `/robots.txt` — generated by `src/app/robots.js`.
- Allows crawling of public content and disallows `/admin`, `/checkout`, `/orders`, `/login`, `/forgot-password`.
- References the sitemap: `Sitemap: <siteUrl>/sitemap.xml`.
- Private pages are additionally `noindex` (see §9) — never rely on robots.txt alone.

## 4. Canonical Strategy

Every indexable page declares an explicit canonical via `alternates.canonical`:

| Page | Canonical |
|---|---|
| `/` | `/` |
| `/about` | `/about` |
| `/originals` | `/originals` |
| `/prints` | `/prints` |
| `/gallery` | `/gallery` |
| `/contact` | `/contact` |
| `/product/[id]` | `/product/[id]` (dynamic) |

Canonicals resolve against `metadataBase` (the `NEXT_PUBLIC_APP_URL` origin), so they are always absolute HTTPS URLs pointing at the preferred version. No query strings.

## 5. Metadata Strategy

- **Root (`src/app/layout.jsx`)**: `metadataBase`, title default + template (`%s | B. Van Sanders`), description, keywords, authors, creator, publisher, robots (+ googleBot: `max-image-preview: large`), Open Graph, Twitter `summary_large_image`, icons, manifest.
- **Every public page** exports unique `title`, `description`, `keywords`, `openGraph` and `twitter` metadata.
- **Titles** (50–60 chars where practical):
  - Home: `B. Van Sanders | Abstract & Pop Art Painter`
  - About: `About B. Van Sanders | Abstract & Pop Artist`
  - Originals: `Original Acrylic Paintings | B. Van Sanders`
  - Prints: `Giclée Art Prints | B. Van Sanders`
  - Gallery: `Art Gallery & Studio Work | B. Van Sanders`
  - Contact: `Contact & Art Commissions | B. Van Sanders`
  - Product: `<Title> <Original Acrylic Painting|Giclée Print> | B. Van Sanders` (dynamic)
- **Descriptions** are unique per page, 150–160 characters, written naturally around real content.
- **OG images**: default is `/assets/portrait.jpg`; product pages use the artwork image when one exists (falls back to the portrait).

## 6. Product SEO

`src/app/product/[id]/page.jsx`:

- `generateStaticParams` — pre-renders all seeded slugs.
- `generateMetadata` — fetches real product data (seeded catalog, or Firestore via the REST helper `fetchProductMetadata`) and returns a **unique** title, description, keywords, canonical, Open Graph and Twitter image per artwork. No generic "Product" metadata.
- The page itself renders server-side **Product + BreadcrumbList JSON-LD** containing the title, description, price (USD), availability (InStock/SoldOut), SKU, brand, and image — so Google understands facts even without executing client JS.
- The visible detail view (`ProductView` → `ProductDetail`) is client-rendered (existing app behavior). JSON-LD + metadata + sitemap guarantee the critical artwork info is server-rendered.
- To add a new artwork: create it in the admin panel. It appears in the sitemap (via `fetchAllProducts`), gets dynamic metadata, canonical, and JSON-LD automatically. No code changes needed.

## 7. Structured Data

Reusable renderer: `src/components/seo/JsonLd.jsx` (escapes `<` to prevent script injection).

| Schema | Where | Contents |
|---|---|---|
| `WebSite` | `/` | name, url, description, publisher |
| `Person` | `/about` | name (+ alternate "Brett Van Sanders"), jobTitle, image, url, email, knowsAbout, bio — **no city/address** (global positioning) |
| `Product` | `/product/[id]` | name, description, sku, brand, category, offers (price, priceCurrency USD, availability, itemCondition, seller) |
| `BreadcrumbList` | `/product/[id]` | Home → Originals/Prints → Artwork |

**Nothing is fabricated**: no reviews, ratings, awards, gallery affiliations, or street addresses.

## 8. Keyword Strategy

Keywords are used naturally in headings, copy, alt text, metadata, and schema — never stuffed. **Global positioning** — no city-specific targeting for now (Denver was removed from all metadata, keywords, and schema).

### Brand
`B. Van Sanders`, `B Van Sanders artist`, `B. Van Sanders painter`, `B. Van Sanders art`

### Style
`abstract art`, `abstract artist`, `pop art`, `pop art artist`, `pop culture art`, `contemporary pop art`, `bold acrylic paintings`, `acrylic on canvas`

### Product
`original acrylic paintings`, `original paintings for sale`, `acrylic paintings for sale`, `pop art paintings`, `giclée art prints`, `fine art prints`, `signed art prints`, `limited edition art prints`

### Intent

## 9. Noindex Routes

These pages export `robots: { index: false, follow: false }`:

- `/login`
- `/forgot-password`
- `/checkout`
- `/checkout/success`
- `/orders` (via `src/app/orders/layout.jsx` — the page is a client component and cannot export metadata itself)
- `/admin` (already noindex)

Public artist/catalog pages are never noindexed.

## 10. Image SEO

- `src/components/cards/ProductArtwork.jsx` — descriptive alt (`"Static Bloom original acrylic painting by B. Van Sanders"`), `loading="lazy"`, `decoding="async"`.
- `src/components/cards/GalleryItem.jsx` — descriptive alt (`"<caption> by B. Van Sanders"`), lazy-loaded.
- Hero logo image is `alt=""` / `aria-hidden` (decorative). Portrait uses `next/image` with a descriptive alt and `priority`.
- Remote Firebase Storage images use plain `<img>` (dynamic URLs — `next/image` isn't applicable) inside fixed-aspect containers, so there's no layout shift.

## 11. Environment Variables

| Variable | Purpose | Required |
|---|---|---|
| `NEXT_PUBLIC_APP_URL` | Production domain for canonicals, sitemap, robots, OG, JSON-LD | **Yes for production** (e.g. `https://www.bvansanders.com`) |
| `NEXT_PUBLIC_FIREBASE_*` | Firebase config (also used by server REST helpers) | Yes |
| `STRIPE_SECRET_KEY` | Server-only Stripe key | Yes |
| `RESEND_API_KEY`, `RESEND_FROM_EMAIL` | Server-only email | Yes |
| `CONTACT_EMAIL` | Studio inbox | Yes |

Never expose `STRIPE_SECRET_KEY`, `RESEND_API_KEY`, or Firebase service-account credentials client-side. All server REST helpers use only public-read Firestore rules + the public `NEXT_PUBLIC_FIREBASE_API_KEY`.

## 12. How to Validate SEO

```bash
npm run lint
npm run build
npm run start
```

Then check:

- `/sitemap.xml` — contains all public routes, no private routes
- `/robots.txt` — disallows listed paths, references sitemap
- `/manifest.webmanifest` — loads without errors
- `curl http://localhost:3000/originals` (or browser view-source) — one `<h1>`, meta title/description/robots, canonical, OG tags
- `curl http://localhost:3000/product/static-bloom` — dynamic metadata + `application/ld+json` Product/BreadcrumbList blocks
- `curl http://localhost:3000/login` — `<meta name="robots" content="noindex, nofollow">`
- External validators:
  - Google Rich Results Test — https://search.google.com/test/rich-results (Product + Breadcrumb schemas)
  - Schema.org validator / validator.schema.org
  - Facebook Sharing Debugger / Twitter Card Validator (OG images)
  - PageSpeed Insights — Core Web Vitals

## 13. Google Search Console

1. Add the property to **Google Search Console** (domain property recommended).
2. Verify the domain (DNS TXT record or HTML file in `public/` — the required value can also be injected via an env var if you prefer dynamic injection).
3. Submit `https://<your-domain>/sitemap.xml` under **Sitemaps**.
4. Use **URL Inspection** on `/`, then key product URLs (e.g. `/product/static-bloom`), and "Request indexing" where appropriate.
5. Monitor **Pages**, **Enhancements** (Breadcrumbs/Product), and **Performance** reports.

## 14. How to Update Product Metadata

- **Existing product**: edit it in the admin panel — title/description/price/image/sold all flow into dynamic metadata, JSON-LD, and the sitemap automatically.
- **New product**: create it in the admin panel — it appears in `/sitemap.xml` (within an hour, `revalidate = 3600`), gets its own canonical + metadata + schema, and is crawlable at `/product/<id>`.
- **Seeded catalog** (`src/data/products.js`) — update the static entries if you change the initial catalog; they drive `generateStaticParams` and build-time metadata.

## 15. Known Constraints

- Visible product-detail content is client-fetched (existing architecture); artwork facts are mirrored in server-rendered JSON-LD + metadata + sitemap so crawlers and AI search engines still capture full artwork information.
- Social profile URLs are not published on the site, so `sameAs` is intentionally omitted from schema (no fabricated links).
- The portrait file (`/assets/portrait.jpg`) serves as the default/fallback OG image; a dedicated 1200×630 OG image would be a nice upgrade but none exists in the project.
